# Changelog — v0.11.2

Commit range: `v0.11.1` → `v0.11.2`

## Engine

- `ManagedDerivationPremiseEngine.populateFromCitations` no longer wraps n ≥ 2 antecedent construction in a `PERMISSIVE_GRAMMAR_CONFIG` save/restore. Standard grammar runs throughout, and the engine's `wrapInsertFormula` rule auto-inserts the formula buffer between `IMPLIES` and `OR`. Output shape changes from `IMPLIES(OR(s1, …, sn), Q)` (shape A) to `IMPLIES(formula(OR(s1, …, sn)), Q)` (shape B) — the canonical shape every other engine path produces. The n = 0 and n = 1 branches are unchanged. `PERMISSIVE_GRAMMAR_CONFIG` is no longer imported in `managed-derivation-premise-engine.ts`.

## Validation

- `validateDerivationStructure` is unchanged. It continues to accept both shape A and shape B, so pre-v0.11.2 stored trees still load. Tightening the validator to require shape B would break load-time validation for any consumer with shape-A rows in their database; that decision is deferred and left to a separate deprecation cycle.

## Tests

- `test/core.test.ts` — `populateFromCitations` describe block: updated the existing n ≥ 2 test to expect 7 expressions and assert the formula-buffer hop; added two new regression tests: an explicit n = 2 structural lock for the formula buffer, and a strict-load vs. auto-normalize-load `combinedChecksum` identity check that round-trips through `ArgumentEngine.fromSnapshot`. The setup helper now also returns `claimLib` so the round-trip test can rebuild the engine.

## Documentation

- `CLAUDE.md` — `populateFromCitations` design rule updated to describe the canonical shape and note the v0.11.2 change.
- `docs/api-reference.md` — `populateFromCitations` section updated; added a "Changed in v0.11.2" callout.
