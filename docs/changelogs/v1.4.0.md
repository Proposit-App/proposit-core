# v1.4.0 changelog

Commit range: `v1.3.1..HEAD`.

## Added

- **`QuotaExhaustedLlmError` + distinct `LLM_QUOTA_EXHAUSTED`
  classification.** The OpenAI Responses provider now JSON-parses the
  429 error body and extracts `error.code ?? error.type`. A 429 whose
  discriminator is `insufficient_quota` throws the new
  `QuotaExhaustedLlmError` (`retryReason: "quota_exhausted"`,
  `status?: number`); every other or unparseable 429 keeps throwing
  `RateLimitLlmError`. (`src/extensions/openai/provider.ts`:
  `classifyHttpError` gains a `providerErrorCode` param + quota
  branch; `src/extensions/openai/errors.ts`: new class.)
- **`quota_exhausted` retry reason + fail-fast wiring.** `TRetryReason`
  gains `"quota_exhausted"`; `classifyError` recognizes the new tag;
  the PATH-B reason→code mapping in `llmStage` maps it to
  `LLM_QUOTA_EXHAUSTED`. Fail-fast is achieved purely by the reason's
  absence from `retryOn` (the existing `break` at the
  not-in-`retryOn` branch), **not** by a hard-coded non-retryable
  branch — so a stage with `retryOn: ["rate_limit"]` still fails a
  quota 429 on attempt 1. No `execute.ts` edits: the throw funnels
  through the single `LlmStageRetryExhaustedError` terminal catch,
  which already copies `err.code` onto `TProcessingFailure.code`.
  (`src/lib/pipelines/stage-helpers.ts`.)
- **SDK-free failure-code constants module.** New
  `src/lib/pipelines/failure-codes.ts` exports `LLM_QUOTA_EXHAUSTED`,
  `LLM_RATE_LIMITED`, `LLM_TRANSIENT_ERROR`, `LLM_NON_RETRYABLE_ERROR`,
  `LLM_UNKNOWN_ERROR`, `OUTPUT_SCHEMA_INVALID`. `stage-helpers.ts` now
  references these constants instead of bare string literals.
- **Public barrel exports.** `QuotaExhaustedLlmError` is exported from
  `src/extensions/openai/index.ts` and re-exported from
  `src/lib/index.ts`. The six failure-code constants are exported via
  `src/lib/pipelines/index.ts` and re-exported from `src/lib/index.ts`.

## Tests

- `test/extensions/openai/provider.test.ts`: new
  "429 quota vs rate-limit classification" block — `insufficient_quota`
  body → `QuotaExhaustedLlmError`; `rate_limit_exceeded` body →
  `RateLimitLlmError`; unparseable body → `RateLimitLlmError`;
  `{"error":{}}` → `RateLimitLlmError`.
- `test/pipelines.test.ts`: new "llmStage — quota-exhaustion
  classification" block — quota fails fast on attempt 1 with
  `LLM_QUOTA_EXHAUSTED` (asserts call count == 1, no retry events);
  quota stays non-retryable under `retryOn: ["rate_limit"]`
  (call count == 1); transient attempt-count pin (== `maxAttempts`);
  constant + class export check. `DEFAULT_RETRY_POLICY` shape test
  asserts `quota_exhausted` absent from `retryOn`.
- `test/mocks/llm.ts`: new `makeQuotaError` helper.
