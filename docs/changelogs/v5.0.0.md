# v5.0.0 changelog

## Added

- `xor` added to `CoreLogicalOperatorType`, the parser AST, and the grammar as a
  variadic (≥2 operand) connective in the same family as `and` and `or`.
- New `ExclusiveDisjunction` grammar rule between `Disjunction` and
  `Implication`; `xor` binds looser than `∨` and tighter than `→`/`↔`. Accepts
  `⊻`, `⊕`, `^` and `xor` (case-insensitive); renders as `⊻`.
- `belnapXor` added to the four-valued evaluation tables, defined from the truth
  components rather than composed from `and`/`or`/`not` so that it is
  associative and a nested chain may be flattened without changing its value.
- `xor` added to the E-1 arity floor, to S-2's valid operator types, and to the
  existing auto-normalization rules and presentable validators wherever `and`
  and `or` are handled.
- Constraint propagation forces the parity remainder on a granted `xor` step.
- `xor` handled in the CLI import switches, the DOT graph label, and the
  pipeline formula-validation stage.

## Changed

- `changeOperator` now permits any swap within an arity class — `{and, or, xor}`
  and `{implies, iff}` — replacing the table that paired each operator with a
  single partner. Strictly widening: nothing previously permitted is now
  refused.

## Notes

- `xor(a, b)` and `not(iff(a, b))` differ at `xor(null, contested)`, which
  answers `null` where the composed reading answers `false`. This is deliberate;
  the composed reading is not associative over the four-valued tables.
