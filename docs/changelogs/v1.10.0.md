# v1.10.0 changelog

Commit range: `v1.9.0..v1.10.0`.

## New

- **`backgroundStreamMode` option on `createOpenAiResponsesProvider`** — third execution branch in `fetchResponseEnvelope` (`provider.ts`): a single streaming create with `{ background: true, stream: true, store: true }` whose SSE stream is consumed live. A background response can only be streamed if it was _created_ with `stream: true`, so this is one create call — not a separate non-streaming submit POST. Response keeps generating server-side after a connection drop. `backgroundStreamMode: true` takes priority over `backgroundMode` when both are set.
- **`onResponseCreated?: (responseId: string) => void` on `TLlmRequest`** (`src/lib/llm/types.ts`) — optional, backward-compatible callback a provider invokes **mid-flight**, the moment the upstream response id is known and **before `respond()` resolves**. In background-stream mode the provider fires it from the first `response.created` SSE event (parsed by `readSseEnvelope`'s new `onResponseId` seam). Synchronous providers leave it uncalled.
- **`retrieveResponse(id, options): Promise<TRetrievedResponse>`** — new exported function from `src/extensions/openai/index.ts`. Passively retrieves a stored OpenAI response by id (GET `/v1/responses/{id}`). Returns `{ status, output?, tokenUsage?, rawResponseId }`. HTTP 404 throws the new `ResponseNotFoundError` (retention window elapsed). Does **not** advance a still-generating background response — use `reconnectStream` for that.
- **`reconnectStream(id, options): Promise<TRetrievedResponse>`** — new exported function from `src/extensions/openai/index.ts`. Reconnects to a stored background response via `GET /responses/{id}?stream=true&starting_after=<cursor>` and consumes the SSE stream to its terminal event, returning the `TRetrievedResponse` shape. This is what **drives a dropped background response to completion** — passive `retrieveResponse` polling leaves a `queued`/`in_progress` response stalled (proven against the live API). `options.startingAfter` defaults to 0. 404 → `ResponseNotFoundError`; honors `signal`; reuses `readSseEnvelope`.
- **`ResponseNotFoundError`** — new typed error class in `src/extensions/openai/errors.ts`, thrown by `retrieveResponse` (and the background poll loop) on 404. **Extends `NonRetryableLlmError`** (no `retryReason` tag → fail-fast; `status: 404`). Carries `responseId` for the caller.
- **`TRetrievedResponse` / `TResponseStatus` types** — exported from `src/extensions/openai/index.ts`.
- **`stage:llm-response-created` pipeline event** — new `TPipelineEvent` variant (`src/lib/pipelines/types.ts`). `llmStage` wires `onResponseCreated` into the request and emits `{ stageId, attempt, responseId }` the moment the id is known — **mid-flight in background-stream mode (before the call resolves)**, or at completion in sync/poll mode — always before `stage:llm-call` on the same attempt, at most once per attempt. `prefixSubPipelineEvent` in `stage-helpers.ts` handles the new variant.
- **`rawResponseId` on `stage:llm-call`** — optional `rawResponseId?: string` field added to the `stage:llm-call` event payload.

## Changed

- **`parseSseEvent`** now returns a discriminated `{ kind: "terminal" | "created", ... }` so the SSE reader recognizes the `response.created` lifecycle event (carrying the id) in addition to the terminal events. `readSseEnvelope` gained an optional `onResponseId` callback fired once when that event is parsed.
- **`getResponseById`** now throws `ResponseNotFoundError` on HTTP 404 rather than routing through `classifyHttpError`. Behavior-preserving: a mid-poll 404 previously surfaced as a generic `NonRetryableLlmError`; `ResponseNotFoundError` is a subclass of it with no `retryReason`, so `llmStage` still classifies it `non_retryable` (fail-fast).
- `createOpenAiResponsesProvider`: `useBackground` is forced `false` when `useBackgroundStream` is `true`, so the two options are composable without mutual exclusion requirements on the caller.
- No-tools guard now covers `useBackgroundStream || useBackground` in a single check.
