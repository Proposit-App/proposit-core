# v1.9.0

## Argument ingestion — conclusion-selection resolves from ranked candidates (`1f45f5f`)

- `conclusion-selection` now returns a confidence-ranked `conclusionCandidates: string[]` (best first) rather than a single `conclusionMiniId | null`. The schema splits into `ConclusionSelectionLlmOutputSchema` (model output: `{ conclusionCandidates, rationale }`) and `ConclusionSelectionOutputSchema` (stage output: adds the resolved `conclusionMiniId`, keeps the candidate list).
- The stage resolves a single conclusion: the first candidate that is a known `normal` claim, else a deterministic relation-graph fallback (highest in-degree terminal sink, document-order tiebreak, relaxes through support cycles), else `null` + a `NO_SINGLE_CONCLUSION` warning. An argument with a support graph is no longer abandoned when the model abstains.
- Downstream `formula-compilation` and `finalize-response-v2` continue to read the resolved `conclusionMiniId`; the candidate list is additive for consumers that want to offer alternates.
- v2 golden-corpus fixtures re-recorded for the new prompt + schema.
