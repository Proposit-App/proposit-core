# v3.3.0 changelog

<changes starting-hash="339b88f" ending-hash="68adfef">

## Changed

- **`EncodableDate` migrated off the removed `Type.Base`.** typebox 1.3.x
  deleted `Type.Base` (`build/type/types/base.mjs` is absent at 1.3.8, and
  `build/typebox.d.mts` no longer re-exports `Base`/`IsBase`), so
  `export class TDateType extends Type.Base` threw
  `TypeError: Class extends value undefined is not a constructor or null` at
  module-evaluation time — before any consumer code ran. The declared range
  `^1.1.14` admitted 1.3.x, so this was reachable by a consumer bump alone.
  `typebox` is now `^1.3.8`.

    `Type.Refine` alone was insufficient. It replaces the `Check`/`Errors`
    surface, but 1.3.8's `Value.Convert` (`build/value/convert/from_type.mjs`)
    dispatches purely on built-in kinds with no user hook, where 1.1.14 had
    `from-base.mjs` calling `Base.Convert`. String→`Date` coercion therefore has no
    home in the Convert pass any more and moved to the decode pass. The shape is
    now `Type.Codec(Type.Refine(Type.Unsafe<Date>({}), isDate, …)).Decode(toDate).Encode(identity)`,
    matching `@proposit/shared`'s independently-defined copy exactly — the two
    resolve one hoisted typebox in the consumer, so a split resolution would leave
    whichever guessed wrong broken.

    `Type.Unsafe<Date>` is load-bearing: `Static` resolves in the Encode direction
    (`static.d.mts:45`), so a conventional `Codec(String)` would have flipped every
    date field's inferred type to `string`. The identity `Encode` is load-bearing
    too — the Encode pipeline is `Clone → EncodeUnsafe → … → Assert`, so a real
    `Date → ISO` encoder would fail its own assert.

- **`Check` now also accepts a serialized date string, not only a `Date`.**
  Forced, not chosen: `Value.Decode` asserts before running decode callbacks, and
  union member selection (`value/codec/from_union.mjs`) skips members that fail
  `Check`, so a strict `instanceof Date` refinement made `Nullable(EncodableDate)`
  unresolvable for any wire value. Numbers remain rejected — the accepted
  encoding is narrowed to date strings, the form `JSON.stringify` emits — so the
  existing assertion that `publishedOn: 12345` fails still holds. The old
  `Convert` leniency toward numbers is gone.

## Fixed

- **`cloneAndStrip` (`src/extensions/citations/ieee/relaxed.ts:73-94`) dropped
  TypeBox's non-enumerable keys.** Latent bug exposed by the migration: it
  preserved `EncodableDate` by reference only because it was a class instance. As
  a plain object it was rebuilt via `Object.entries`, silently discarding the
  non-enumerable `~refine`/`~codec`/`~unsafe` keys, which would have made every
  relaxed date field match _any_ value. Non-enumerable descriptors are now
  carried across.
- `src/cli/storage/variables.ts:38` and `src/lib/parsing/argument-parser.ts:261`
  assert their result type explicitly: 1.3.8 dropped `Value.Parse`'s inferable
  result type parameter, which those two sites had relied on to widen the
  declared return type. Unrelated to dates.

## Added

- Added `scripts/first-time-setup.sh`, the per-repo tier of the workspace
  onboarding flow (invoked by the orchestration repo's `scripts/setup.sh`). It
  installs nothing: it checks prerequisites (node ≥ 22.3, pnpm, `node_modules/`),
  confirms `core.hooksPath` is `.githooks` (repairing it only if an install
  skipped the `prepare` script), then runs `pnpm run check` and
  `bash scripts/smoke-test.sh`. Idempotent, exits non-zero on any failure.
