# v1.0.1 changelog

`v1.0.1` is a one-fix patch on top of `v1.0.0`. It corrects an
engine-internal contract violation surfaced by `proposit-server`'s
cycle 4d when it activated the cross-tier validation gates against the
publish flow.

## Cross-repo dependencies

- **No new dependencies.** Local patch only.
- Server bumps `@proposit/proposit-core` from `^1.0.0` to `^1.0.1`
  after this release publishes; mobile bumps in lockstep.

## Fix

Single commit (hash filled at tag time): `fix(grammar): wrapExpression
and changeOperator-SPLIT use [0, 1] for implies/iff children to
satisfy S-8`.

### `src/lib/core/expression-manager.ts`

`wrapExpression` now branches on `operator.operator === "implies" ||
=== "iff"`. The binary case pins both children to literal positions
`[0, 1]`. The variadic case (`and` / `or`) keeps the existing
`[POSITION_INITIAL, midpoint(POSITION_INITIAL, POSITION_MAX)]` pattern
(and the mirror with `rightNodeId`).

### `src/lib/core/premise-engine.ts`

The SPLIT branch inside `changeOperator` (the path that rebalances a
3+-child operator into a new binary sub-operator under a formula
buffer) gets the same `isBinaryOp` branch defensively. The path is
unreachable for `implies` / `iff` today because S-5 throws at
`addExpression` time on the new sub-operator before the reparent
fires, but the explicit `[0, 1]` documents the intended end-state in
case S-5 mutation-time enforcement is ever relaxed.

### `test/core.test.ts`

Five new regression tests inside the `wrapExpression` describe block:
implies-left-existing, implies-right-existing, iff, and the `and` /
`or` regression guards (midpoint spacing preserved,
`validate("structural")` returns no violations).

### Change request

The cross-repo change request that scoped this fix
(`docs/change-requests/2026-05-15-createExpressionWithOperator-s8-position-bug.md`,
authored from the server side via the workspace symlink) was
untracked in this repo's main history. It is removed from the worktree
per the change-request lifecycle convention in this repo's `CLAUDE.md`.

## Why this didn't surface earlier

The bug has been latent in `wrapExpression` since the
`@proposit/proposit-core` 1.0.0 four-tier grammar rewrite. It was
masked because:

1. Pre-1.0 server flows did not call `engine.validate('structural')`
   (the four-tier validator did not exist).
2. Post-1.0 the server's persistence path captured changesets via
   snapshot-diff, which silently accepted the `[0, 1073741823]`
   positions as just-numbers.
3. Server's cycle 4d (`grammar-tiers/server`) activated
   `validate('presentable')` (a superset of `validate('structural')`)
   as a publish-time gate. That gate began firing S-8 violations at
   every implies/iff wrap, surfacing the contract mismatch.

The fix restores the engine's own internal consistency. No external
contract changed; consumers were already entitled to a clean
`validate('structural')` result after `wrapExpression`.
