# v1.1.0 changelog

`v1.1.0` is a minor release shipping a new framework + a new provider
extension + a new ingestion pipeline + the CLI cutover, decomposed
into four developer slices (1A → 1C) plus two reviewer folds (1A.1,
1C.1) and one in-cycle fold (1B.1).

The slices were authored on the `ingestion-pipeline/phase-1`
feature branch and merged into `main` via `--no-ff` to preserve
slice structure in `git log`.

## Cross-repo dependencies

- **New optional `peerDependency` on `openai >= 4.0.0`** (declared
  in slice 1B; not imported by V1, kept for forward-looking
  insurance — see the slice 1B section below).
- Server (`proposit-server`) and mobile (`proposit-mobile`) can bump
  their `@proposit/proposit-core` dep to `^1.1.0` to pick up the new
  exports. No breaking changes; bumping is optional.

## Slice 1A — pipeline framework primitives + abstract LLM interface

Hash range: `89adac1..7e28be0` (3 commits) + `edccb33` (1A.1 fold).

### `src/lib/pipelines/`

New package containing the DAG executor + stage helpers:

- `types.ts` — `TStage<TOutput>`, `TPipeline<TInput, TOutput>` (with
  `finalize: { dependsOn, run }`), `TStageContext` (with `get<T>` +
  `stageStatus`), `TProcessingFailure`, `TPipelineResult<TOut>`,
  `TPipelineEvent`, `TDepSpec` (the `string | TOptionalDep` union),
  `optional(id)` helper.
- `execute.ts` — `executePipeline(pipeline, input, deps)` scheduler.
  Validates input + DAG up front (cycles, self-deps, unknown deps);
  runs eligible stages concurrently bounded by `concurrencyLimit`
  (default 4); enforces `ctx.get` / `ctx.stageStatus` strictness
  (stages can only query upstreams in their `dependsOn`); routes
  retry-exhaustion + abort + sub-pipeline failures into typed
  errors the executor recognizes; emits a typed event stream.
- `stage-helpers.ts` — `deterministicStage`, `llmStage`,
  `subPipelineStage`, `DEFAULT_RETRY_POLICY`, the error classes
  (`LlmStageRetryExhaustedError`, `StageAbortedError`,
  `SubPipelineFailedError`).
- `index.ts` — public barrel.

### `src/lib/llm/`

New package containing the abstract `TLlmProvider` interface:

- `types.ts` — `TLlmProvider`, `TLlmRequest<T>`, `TLlmResponse<T>`,
  `TToolSpec` discriminated union, `TLlmModel` /
  `TReasoningEffort` literal types, `TLlmTokenUsage`.
- `index.ts` — public barrel.

### `src/lib/index.ts`

Re-exports the new public surface from the package root.

### `test/pipelines.test.ts` + `test/mocks/llm.ts`

Mock-provider-driven unit tests covering DAG validation,
concurrency, failure propagation, schema validation, retry, token
usage aggregation, cancellation, pipeline events, finalize
semantics, and `subPipelineStage`. Mock provider keys responses by
stage id (extracted from a `<!--stage-id: <id> -->` comment in the
system prompt) or by call order.

### Slice 1A.1 — dual-review fold

`edccb33` folds five reviewer findings:

- P2 #1 — Mid-flight aborted stage surfaces as `skipped` (not
  `failed` with `LLM_NON_RETRYABLE_ERROR`); new `StageAbortedError`
  class.
- P3 #1 — Abort fast-path emits `stage:start` before `stage:end`
  for consistent paired events (SSE bridge in a future release
  will rely on this).
- P3 #2 — Optional-dep cycle detection now has a pinned test.
- P3 #3 — `ctx.stageStatus(id)` enforces the same `dependsOn`
  allowlist as `ctx.get(id)`.
- P3 #5 — `subPipelineStage` null-output throws
  `SubPipelineFailedError` (the previous misnamed
  `LlmStageRetryExhaustedError`).

Type aliases adopt the repo-standard `T*` prefix (`TStage`,
`TPipeline`, `TStageContext`, `TProcessingFailure`,
`TPipelineResult`, `TPipelineEvent`, `TDepSpec`, `TOptionalDep`,
`TLlmProvider`, `TLlmRequest`, `TLlmResponse`, `TToolSpec`).

## Slice 1B — OpenAI Responses-API provider extension

Hash range: `6c804b4..f823e16` (4 commits) + `e69afed` (1B.1 fold).

### `src/extensions/openai/`

New extension package containing the concrete `TLlmProvider`:

- `provider.ts` —
  `createOpenAiResponsesProvider({ apiKey, model?, baseUrl?, fetch?, maxToolCallRounds? })`.
  Raw `fetch` to `https://api.openai.com/v1/responses` (the
  Responses API, not the deprecated Chat Completions endpoint).
  Caps the function-tool agent loop at 6 rounds by default.
- `structured-output.ts` — inlined TypeBox → OpenAI strict-mode JSON
  Schema converter. Supported primitives: `Object`, `Array`,
  `String`, `Number`, `Integer`, `Boolean`, `Union` of literals,
  `Literal`, `Optional`, `Record`. Unsupported primitives throw at
  converter-build time. `Type.Optional(...)` renders as
  `anyOf: [<T>, { type: "null" }]` with the property name kept in
  `required` (the only strict-mode-valid encoding of optionality).
- `errors.ts` — `TransientLlmError`, `RateLimitLlmError`,
  `SchemaValidationLlmError`, `NonRetryableLlmError`,
  `ToolLoopExhaustedError`. The framework's `llmStage` retry policy
  keys off the error class's `retryReason` tag.
- `types.ts` — extension-internal Responses-API request/response
  shapes.
- `index.ts` — public barrel.

### `src/cli/llm/`

Adapter body moved into `src/extensions/openai/provider.ts`; the
CLI factory now constructs the new provider. The pre-1.1.0
chat-completions code is gone.

### `src/cli/commands/parse.ts`

Switched to construct the new provider via `createLlmProvider`. CLI
behavior is preserved end-to-end; the dry-run path was used for
smoke verification during slice 1B.

### `package.json`

Adds `peerDependencies.openai = ">=4.0.0"` with
`peerDependenciesMeta.openai.optional = true`. The V1
implementation uses raw `fetch` only; the peerDep is forward-looking
insurance.

Adds the subpath export `./extensions/openai` pointing at
`./dist/extensions/openai/index.js` so callers can import directly
from `@proposit/proposit-core/extensions/openai` and tree-shake the
provider out of their build if not needed.

### `src/lib/index.ts`

Re-exports the new public surface
(`createOpenAiResponsesProvider`, `TCreateOpenAiResponsesProviderOptions`,
the five error classes) from the package root.

### `test/extensions/openai/`

`structured-output.test.ts` covers 8-10 TypeBox shapes and the
unsupported-primitive throw path. `provider.test.ts` covers
request-body shape, response parsing, tool-call agent loop,
function-call/output echo + multi-tool-call, error classification
(5xx / 429 / 400 / 422 / other 4xx), and abort propagation.
`test/integration/parse-api.test.ts` is the gated live integration
test that hits the real OpenAI API.

### Slice 1B.1 — dual-review fold

`e69afed` folds four reviewer findings:

- P1 #1 — Tool agent loop echoes `function_call` items back into
  the next-round `input` array (matched by `call_id` to their
  `function_call_output`), preserving Responses-API conversation
  state. Multi-tool-call test added.
- P1 #2 — `Type.Optional` properties render as `anyOf` with null +
  stay in `required`. Strict-mode-invalid pre-fold; correct
  post-fold.
- P2 #1 — HTTP 400 routes to `NonRetryableLlmError` (not
  retried — typically a converter bug); 422 stays on
  `SchemaValidationLlmError` (the model can re-roll a strict-mode
  violation).
- P2 #2 — Inline doc on the rare simultaneous
  `function_call` + final `message` case.

## Slice 1C — v1 single-shot ingestion pipeline + golden corpus

Hash range: `460fb1f..af752d3` (5 commits) + `75c1738` (1C.1 fold).

### `src/extensions/argument-ingestion/`

New extension package containing the v1 pipeline + shared helpers:

- `v1-single-shot.ts` —
  `createIngestionV1Pipeline(extension, options?)`. One `llmStage`
  (`parse-argument`) calls the configured LLM with
  `buildParsingPrompt(extension.responseSchema)` + the raw input
  text; finalize merges the response with an empty
  `processingFailures: []` slot.
- `shared/finalize-response.ts` — passthrough finalize merger. v1
  attaches an empty `processingFailures` slot to the LLM response;
  v2 will populate it from per-stage warnings/errors.
- `shared/role-derivation.ts` — claim-role assigner. v1 trusts the
  LLM's self-assigned roles; v2 will derive roles from the
  relations graph.
- `shared/basics-extension.ts` — default `TIngestionExtension`
  composing the basics-tier per-entity field shapes.
- `shared/types.ts` — `TIngestionExtension` descriptor +
  `TIngestionInput` shape.
- `index.ts` — public barrel.

### `src/extensions/basics/schemata.ts`

Per-entity extension consts (`BasicsNormalClaimExtension`,
`BasicsCitationClaimExtension`, `BasicsAxiomaticClaimExtension`,
`BasicsClaimExtension`, `BasicsVariableExtension`,
`BasicsPremiseExtension`, `BasicsArgumentExtension`) are promoted
to exports so the ingestion extension can compose against them
without duplication. Composed `BasicsParsingSchema` is unchanged.

### `src/cli/commands/parse.ts`

CLI parse command now routes through the v1 pipeline. Adds a
`--pipeline <v1|v2>` flag with default `v1`. Passing `v2` rejects
with "v2 pipeline not yet shipped — coming in Phase 2"; unknown
values reject with a "Supported: v1" message. The `output === null`
branch is wired with a forward-compat comment for v2's
irresolvable-conclusion outcomes.

### `src/lib/index.ts`

Re-exports the new public surface (`createIngestionV1Pipeline`,
`basicsExtension`, `finalizeResponse`, `deriveRoles`, the
`TIngestionExtension` / `TIngestionInput` /
`TCreateIngestionV1PipelineOptions` types) from the package root.

### `test/extensions/argument-ingestion/`

- `v1-single-shot.test.ts` — pipeline shape, happy-path mock-driven
  run, null-argument passthrough, schema-invalid retry exhaustion,
  per-call model override.
- `finalize-response.test.ts` — passthrough + failure attachment +
  no input mutation.
- `role-derivation.test.ts` — v1 LLM-passthrough role assignment.
- `recording-provider.ts` + `recording-provider.test.ts` —
  SHA-256-keyed record/replay `TLlmProvider`. Hash includes
  `model`, `systemPrompt`, `userMessage`, `outputSchema`. Replay
  miss throws `RecordedPromptStaleError`. Includes a prompt-drift
  end-to-end test that records a v1 run, replays with drifted user
  message, asserts the executor surfaces the stale-prompt error as
  a stage failure.
- `e2e.test.ts` — golden-corpus driver. Record mode invokes the
  real OpenAI provider once per fixture; replay mode runs from
  `recorded-llm.json` files (no API key needed). 5 fixtures
  recorded + committed: `straightforward`, `with-url-citation`,
  `with-axiom`, `ambiguous-conclusion`, `enthymeme`.

### Slice 1C.1 — dual-review fold

`75c1738` folds seven reviewer findings:
