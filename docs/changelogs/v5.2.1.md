# v5.2.1 changelog

## Fixed

- Free-text String fields no longer carry a `maxLength` in the wire schema
  `typeboxToOpenAiSchema` and the chat-completions `typeboxToJsonSchema`
  produce. `projectStringLengthHint` used to send `floor(maxLength * 0.9)`
  there, which older OpenAI models ignored but `gpt-6-sol` enforces: it stopped
  generating at the cap, so every basics claim title (`maxLength: 50`, sent as 45) that ran long came back cut off mid-word ("…major politicians since
  177"). The shrunk budget is now stated only in `description`
  ("…; at most 45 characters"). Exact-value fields (a `format`, or a
  `maxLength` of 16 or less) keep their `maxLength` as before.
- Every place that shortens an over-long string now ends it on a whole word
  followed by "…" instead of slicing mid-word: the pipeline stage output
  clamp (`clampMaxLengthStrings`), the parser's `clampMaxLengths`, and the
  authored premise title and argument title caps in `finalizeResponseV2`. A
  value with no space inside the limit (a URL, one long token) is still cut at
  the limit exactly, with no "…".
