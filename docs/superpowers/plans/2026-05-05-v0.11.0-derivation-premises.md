# v0.11.0 — Derivation Premises Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a structurally-constrained `derivation` premise type with opt-in enforcement via `ManagedDerivationPremiseEngine`, plus citation-snapshot helper and evaluation pre-flight.

**Architecture:** A `type: "freeform" | "derivation"` discriminator on `TCorePremise`. The classic `PremiseEngine` remains permissive; `ManagedDerivationPremiseEngine extends PremiseEngine` enforces structural rules (consequent slot is locked to the derived claim's variable, root must be `implies`/`iff` or naked variable). Evaluation pre-flight in `ArgumentEngine.validateEvaluability` catches structurally-broken derivation premises before evaluation. A new `ArgumentEngine.ensureClaimBoundVariable` API powers `populateFromCitations` and is independently useful.

**Tech Stack:** TypeScript, TypeBox schemas (`Type.Union` discriminated unions), Vitest, pnpm, ESM.

**Spec:** [`docs/superpowers/specs/2026-05-05-derivation-premises-design.md`](../specs/2026-05-05-derivation-premises-design.md)

**Dependency:** v0.10.0 (`ClaimCitationLibrary`, `type: "normal" | "citation"` on claims, 5-namespace `ForkLibrary`) — already shipped to local main as of `e399779`.

```typescript
import type {
    TCoreDerivationPremise,
    TCorePropositionalExpression,
    TCorePropositionalVariable,
} from "../schemata/propositional.js"
import type { TInvariantValidationResult } from "../types/validation.js"
import { DERIVATION_STRUCTURE_INVALID } from "../types/validation.js"

/**
 * Validate that a derivation premise's expression tree conforms to the
 * structural rules in the v0.11.0 spec:
 *
 *   - Root must be either a single variable expression for the derived
 *     claim's variable (naked form), or an `implies`/`iff` operator with
 *     arity 2.
 *   - When the root is `implies`/`iff`:
 *       - position 0 (antecedent slot) is any valid expression tree.
 *       - position 1 (consequent slot) is exactly the variable expression
 *         for the derived claim's variable. No operator subtree, no other
 *         variable, no formula wrapper.
 *
 * Returns a `TInvariantValidationResult` with one violation per detected
 * rule break, all using `DERIVATION_STRUCTURE_INVALID` (specific message
 * differentiates them).
 */
export function validateDerivationStructure(
    premise: TCoreDerivationPremise,
    expressions: TCorePropositionalExpression[],
    variables: TCorePropositionalVariable[]
): TInvariantValidationResult {
    const violations: TInvariantValidationResult["violations"] = []

    // 1. Locate the claim-bound variable for derivedClaimId.
    const consequentVariable = variables.find(
        (v) => "claimId" in v && v.claimId === premise.derivedClaimId
    )
    if (!consequentVariable) {
        violations.push({
            entityType: "premise",
            entityId: premise.id,
            code: DERIVATION_STRUCTURE_INVALID,
            message: `No claim-bound variable for derivedClaimId ${premise.derivedClaimId} in this argument`,
        })
        return { violations }
    }

    // 2. Find the root expression (parentId === null).
    const rootExpressions = expressions.filter(
        (e) => e.premiseId === premise.id && e.parentId === null
    )
    if (rootExpressions.length === 0) {
        violations.push({
            entityType: "premise",
            entityId: premise.id,
            code: DERIVATION_STRUCTURE_INVALID,
            message: "Derivation premise has no root expression",
        })
        return { violations }
    }
    if (rootExpressions.length > 1) {
        violations.push({
            entityType: "premise",
            entityId: premise.id,
            code: DERIVATION_STRUCTURE_INVALID,
            message: "Derivation premise has multiple root expressions",
        })
        return { violations }
    }
    const root = rootExpressions[0]

    // 3. Validate root shape.
    if (root.type === "variable") {
        // Naked form — must reference the consequent variable.
        if (root.variableId !== consequentVariable.id) {
            violations.push({
                entityType: "premise",
                entityId: premise.id,
                code: DERIVATION_STRUCTURE_INVALID,
                message: `Naked-form root variable ${root.variableId} does not reference derivedClaimId's variable ${consequentVariable.id}`,
            })
        }
        return { violations }
    }

    if (
        root.type === "operator" &&
        (root.operator === "implies" || root.operator === "iff")
    ) {
        // Arity-2 form — antecedent at position 0, consequent at position 1.
        const children = expressions
            .filter((e) => e.parentId === root.id)
            .sort((a, b) => (a.position ?? 0) - (b.position ?? 0))

        if (children.length !== 2) {
            violations.push({
                entityType: "premise",
                entityId: premise.id,
                code: DERIVATION_STRUCTURE_INVALID,
                message: `Derivation root ${root.operator} must have arity 2 (got ${children.length})`,
            })
            return { violations }
        }

        const consequent = children[1]
        if (
            consequent.type !== "variable" ||
            consequent.variableId !== consequentVariable.id
        ) {
            violations.push({
                entityType: "premise",
                entityId: premise.id,
                code: DERIVATION_STRUCTURE_INVALID,
                message: `Consequent slot (position 1) must be the variable expression for derivedClaimId's variable`,
            })
        }
        return { violations }
    }

    violations.push({
        entityType: "premise",
        entityId: premise.id,
        code: DERIVATION_STRUCTURE_INVALID,
        message: `Derivation premise root must be a variable expression or implies/iff operator (got ${root.type === "operator" ? root.operator : root.type})`,
    })
    return { violations }
}
```

Note on the violation `code`: the spec lists multiple specific codes (`DERIVATION_CONSEQUENT_LOCKED`, `DERIVATION_ROOT_OPERATOR_INVALID`) for managed engine mutation rejection. This validation utility uses the broader `DERIVATION_STRUCTURE_INVALID` code with a descriptive message — the specific codes are reserved for managed engine mutation paths in Task 6. The `validateEvaluability` integration (Task 11) emits `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION` based on these violations.

import { PremiseEngine } from "./premise-engine.js"
import type {
    TCoreDerivationPremise,
    TCorePropositionalExpression,
    TCorePropositionalVariable,
    TCorePremise,
} from "../schemata/propositional.js"
import { validateDerivationStructure } from "../utils/derivation-validation.js"
import {
    DERIVATION_TYPE_MISMATCH,
    DERIVATION_STRUCTURE_INVALID,
} from "../types/validation.js"
import { InvariantViolationError } from "./errors.js" // verify exact path

/**
 * A managed engine for derivation premises that enforces the structural
 * rules from the v0.11.0 spec on every mutation.
 *
 * Construction validates the premise type and the expression tree shape.
 * Mutations that would break the derivation invariant (e.g., editing the
 * consequent slot, changing the root operator inappropriately) throw with
 * specific error codes.
 *
 * The classic `PremiseEngine` is permissive and allows mutations that
 * leave a derivation premise temporarily or permanently invalid. The
 * managed engine wraps it for safe, structurally-enforced editing.
 */
export class ManagedDerivationPremiseEngine<
    TPremise extends TCorePremise = TCorePremise,
    TExpr extends TCorePropositionalExpression = TCorePropositionalExpression,
    TVar extends TCorePropositionalVariable = TCorePropositionalVariable,

            `Cannot change derivation root operator to "${newOperator}"; must be implies or iff`
        )

    const root = this.expressions.get(this.rootExpressionId!)
    if (!root) return undefined
    if (root.type === "variable") {
        // Naked form — the root IS the consequent.
        return root.id

    if (root.type === "operator" && (root.operator === "implies" || root.operator === "iff")) {
        const children = this.expressions.list()
            .filter((e) => e.parentId === root.id)
            .sort((a, b) => (a.position ?? 0) - (b.position ?? 0))
        return children[1]?.id
    }

 * premise from the current global citations of the derived claim.
 *
 * Looks up `citationLib.getCitationsForCitingClaim(derivedClaimId)` and

 *   - n = 0: leaves the premise unchanged (typically naked-Q form).

 *   - n ≥ 2: IMPLIES(OR(VariableExpression(S1), ..., VariableExpression(Sn)),
 *            VariableExpression(Q))
 *
 * Ensures a claim-bound variable exists for each cited source via
 * `argumentEngine.ensureClaimBoundVariable(citation.sourceClaimId)`.
 *
 * @throws InvariantViolationError(DERIVATION_ANTECEDENT_NON_EMPTY) when
 *         the premise's root expression is an `implies`/`iff` operator
 *         with a non-null position-0 child (i.e., antecedent already
 *         present). The caller decides whether to delete and re-create
 *         the premise or re-use the existing structure.
 */
public populateFromCitations(citationLib: ClaimCitationLibrary): void {
    const derivedClaimId = (this.premise as TCoreDerivationPremise).derivedClaimId

    // 1. Detect non-empty antecedent and reject.
    const root = this.expressions.get(this.rootExpressionId!)
    if (root && root.type === "operator" && (root.operator === "implies" || root.operator === "iff")) {
        const positionZeroChild = this.expressions.list().find(
            (e) => e.parentId === root.id && e.position === 0
        )
        if (positionZeroChild) {
            throw new InvariantViolationError(
                DERIVATION_ANTECEDENT_NON_EMPTY,
                "populateFromCitations: derivation premise already has a non-empty antecedent"
            )
        }
    }

    // 2. Look up citations for the derived claim.
    const citations = citationLib.getCitationsForCitingClaim(derivedClaimId)
    if (citations.length === 0) {
        return // Nothing to populate.
    }

    // 3. Ensure variables for each cited source exist.
    const sourceVariables = citations.map((c) =>
        this.argumentEngine.ensureClaimBoundVariable(c.sourceClaimId)
    )

    // 4. Build the antecedent tree using the parent class's mutation API.
    //    (Using `super.addExpression(...)` to bypass our own override's
    //    well-formedness check during construction — the tree is in flux
    //    until populated.)
    if (citations.length === 1) {
        // IMPLIES(VariableExpression(S1), VariableExpression(Q))
        // ... build via super.addExpression / super.insertExpression
    } else {
        // IMPLIES(OR(...), VariableExpression(Q))

Add design rules:

```markdown
- **Premise type discriminator:** Every `TCorePremise` has an immutable `type: "freeform" | "derivation"` field. `"derivation"` premises also carry a required, immutable `derivedClaimId: UUID`. Both are part of `premiseFields` for checksum purposes; mutating either via persistence-layer tampering is detectable as a checksum mismatch. `createPremise` and `createPremiseWithId` accept a typed-bag options argument (with backward-compat overload for legacy positional `(extras, symbol)` calls).
- **Derivation premise structure:** Root expression is either a single variable expression for the derived claim's variable (naked form), or an `implies`/`iff` operator with arity 2 where position 0 is the antecedent and position 1 is exactly the variable expression for the derived claim's variable. Both `implies` and `iff` are accepted as the root operator, but their evaluation differs: `implies` is one-way, `iff` propagates both directions.
- **ManagedDerivationPremiseEngine:** Subclass of `PremiseEngine` that enforces derivation rules on every mutation. Construct via `new ManagedDerivationPremiseEngine(premise, ...)` or `ManagedDerivationPremiseEngine.fromSnapshot(...)`; both validate type and structure at construction. Mutation methods are overridden to reject illegal operations (e.g., `DERIVATION_CONSEQUENT_LOCKED` for editing the consequent slot, `DERIVATION_ROOT_OPERATOR_INVALID` for changing the root to non-implies/non-iff). The classic `PremiseEngine` is permissive and does not enforce these — derivation-broken state is allowed mid-mutation and is caught at evaluation pre-flight.
- **Evaluation pre-flight:** `ArgumentEngine.validateEvaluability` (and therefore both `evaluate` and `checkValidity`) walks every `type: "derivation"` premise and validates its structural conformance. Violations are surfaced with code `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION`. The public `validateDerivationStructures()` method exposes the derivation-only subset for ad-hoc inspection.
- **`ensureClaimBoundVariable`:** New public method on `ArgumentEngine`. Idempotently materializes a claim-bound variable for the given claim id, using the current claim version from `ClaimLibrary` and an auto-generated symbol. Throws `CLAIM_NOT_FOUND` when the claim is not in the library. Used internally by `createPremise({type: "derivation"})` and `populateFromCitations`; also independently useful for apps.
- **`populateFromCitations`:** One-shot snapshot helper on `ManagedDerivationPremiseEngine`. Builds the antecedent from the citation library's current edges for the derived claim. n=0 leaves naked-Q; n=1 produces IMPLIES(S1, Q); n≥2 produces IMPLIES(OR(S1, ..., Sn), Q). Refuses if the antecedent is already non-empty (`DERIVATION_ANTECEDENT_NON_EMPTY`); the caller decides whether to re-create the premise. Non-recursive — does not invoke on cited claims' derivation premises.
- **Naked-Q dependency on `collapseEmptyFormula`:** The naked-Q form (root = single variable expression for derived claim's variable) arises naturally from antecedent collapse only when the `collapseEmptyFormula` autoNormalize flag is enabled. Apps that want clean naked-Q semantics must enable the flag; the spec documents the dependency without mandating it. Recovery from intermediate state (when flag is off) is via `addExpression` of a new antecedent.
```

# Release notes — v0.11.0

This release introduces structurally-constrained derivation premises:

## What's new

- **Derivation premise type.** Every premise now carries `type: "freeform" | "derivation"`. Derivation premises also carry a required, immutable `derivedClaimId` — a structural commitment to deriving a single named claim. The classic freeform premise is unchanged.
- **`ManagedDerivationPremiseEngine`.** Opt-in subclass of `PremiseEngine` that enforces the derivation invariant on every mutation: you cannot edit the consequent slot, cannot change the root operator inappropriately, and cannot bulk-load a malformed expression set. The classic engine remains permissive — temporarily-invalid states are allowed mid-mutation and caught at evaluation time.
- **`populateFromCitations` helper.** One-shot citation snapshot. Builds the antecedent from the citation library's current edges. n=0 leaves the premise as naked-Q (a structural symptom of "no support given"); n=1 produces `IMPLIES(S1, Q)`; n≥2 produces `IMPLIES(OR(S1, ..., Sn), Q)`.
- **`ensureClaimBoundVariable` API.** Idempotent variable materialization on `ArgumentEngine`. Useful beyond `populateFromCitations` for apps that programmatically reference claims.
- **Evaluation pre-flight.** `ArgumentEngine.evaluate` and `checkValidity` now refuse to silently proceed on a structurally-broken derivation premise — they return a validation result with `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION`.
