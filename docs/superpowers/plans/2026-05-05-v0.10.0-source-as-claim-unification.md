# Source-as-Claim Unification (v0.10.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unify `Source` into `Claim` under a single library with a `type: "normal" | "citation"` discriminator, rename `ClaimSourceLibrary` → `ClaimCitationLibrary` with new strictness + acyclicity invariants, and migrate the CLI's persisted state on first v0.10.0 startup.

**Architecture:** Single coherent breaking change executed as one PR with staged commits. Bottom-up dependency order: schemas → constants/types → libraries → engines → parsing → extensions → CLI → tests → docs → version bump. Behavioral additions (type immutability, source-side strictness, acyclicity) use TDD; mechanical renames are bulk-applied with verification via `pnpm typecheck` + `pnpm test` at phase boundaries.

**Tech Stack:** TypeScript, TypeBox, Vitest, ESLint, pnpm.

**Spec reference:** `docs/superpowers/specs/2026-05-05-source-as-claim-design.md`

- [ ] **Step 2: Add the cycle detection method**

Inside `claim-citation-library.ts`, add a private method:

```ts
private wouldCreateCycle(
    citingClaimId: string,
    sourceClaimId: string
): boolean {
    // Optimization: if citing-side is normal, it can never appear on source side, so no cycle is reachable.
    const citingClaim = this.claimLookup.get(citingClaimId, /* any version */ 0)
    // Note: we look up any version since cycle detection is ID-only.
    // We use a helper that scans the claim library for any matching ID.
    const citingClaimAnyVersion = this.findAnyVersionOfClaim(citingClaimId)
    if (citingClaimAnyVersion?.type === "normal") return false

    // DFS from sourceClaimId following outgoing source edges.
    // Edges: any citation where citingClaimId === current node (ID-only).
    const visited = new Set<string>()
    const stack: string[] = [sourceClaimId]
    while (stack.length > 0) {
        const node = stack.pop()!
        if (node === citingClaimId) return true
        if (visited.has(node)) continue
        visited.add(node)
        // Find all citations where citingClaimId === node, follow to sourceClaimId
        for (const citation of this.associations.values()) {
            if (citation.citingClaimId === node) {
                stack.push(citation.sourceClaimId)
            }
        }
    }
    return false
}

private findAnyVersionOfClaim(
    claimId: string
): { type: "normal" | "citation" } | undefined {
    // The claimLookup is keyed by (id, version). We need to probe versions.
    // Pragmatic approach: look up version 0 first; if that exists, use its type.
    // Type is immutable across versions, so any existing version's type is authoritative.
    for (let v = 0; v < 1000; v++) {
        const claim = this.claimLookup.get(claimId, v)
        if (claim) return claim
    }
    return undefined
}
```

Then call `wouldCreateCycle` in `add()` after the strictness check:

```ts
import fs from "node:fs/promises"
import path from "node:path"
import { getStateDir } from "../config.js"

const MARKER = ".proposit-v0.10"

export async function migrateV010(): Promise<void> {
    const stateDir = getStateDir()
    const markerPath = path.join(stateDir, MARKER)

    // Step 1: Detection — skip if marker exists
    try {
        await fs.access(markerPath)
        return // Already migrated.
    } catch {}

    // Step 2: Source extras collision check
    await checkSourceExtrasCollision(stateDir)

    // Step 3: Sources → claims conversion
    await convertSourcesToClaims(stateDir)

    // Step 4: Existing claim type backfill
    await backfillClaimTypes(stateDir)

    // Step 5: Associations → citations conversion
    await convertAssociationsToCitations(stateDir)

    // Step 6: Forks fold
    await foldForkSourcesIntoClaims(stateDir)

    // Step 7: Checksum recompute
    await recomputeChecksums(stateDir)

    // Step 8: Acyclicity validation
    await validateAcyclicity(stateDir)

    // Step 9: Marker write
    await fs.writeFile(markerPath, new Date().toISOString())

    process.stderr.write(
        `[proposit] Migrated state directory to v0.10.0 format at ${stateDir}\n`
    )
}

async function readJsonFile<T>(filePath: string): Promise<T | null> {
    try {
        const content = await fs.readFile(filePath, "utf-8")
        return JSON.parse(content) as T
    } catch {
        return null
    }
}

async function writeJsonFile(filePath: string, data: unknown): Promise<void> {
    await fs.writeFile(filePath, JSON.stringify(data, null, 2))
}

async function checkSourceExtrasCollision(stateDir: string): Promise<void> {
    const sourcesPath = path.join(stateDir, "sources.json")
    const snapshot = await readJsonFile<{ sources?: { id: string; type?: unknown }[] }>(
        sourcesPath
    )
    if (!snapshot || !snapshot.sources) return
    const colliding = snapshot.sources.filter((s) => s.type !== undefined)
    if (colliding.length > 0) {
        const ids = colliding.map((s) => s.id).join(", ")
        throw new Error(
            `[proposit migration] Cannot migrate: source records have a 'type' extra that would collide with the new top-level 'type' field. Conflicting source IDs: ${ids}. Rename the extra (e.g., to 'kind') in sources.json and re-run.`
        )
    }
}

async function convertSourcesToClaims(stateDir: string): Promise<void> {
    const sourcesPath = path.join(stateDir, "sources.json")
    const claimsPath = path.join(stateDir, "claims.json")
    const sourcesSnapshot = await readJsonFile<{
        sources?: Array<Record<string, unknown>>
    }>(sourcesPath)
    if (!sourcesSnapshot || !sourcesSnapshot.sources) return
    const claimsSnapshot =
        (await readJsonFile<{ claims?: Array<Record<string, unknown>> }>(
            claimsPath
        )) ?? { claims: [] }
    if (!claimsSnapshot.claims) claimsSnapshot.claims = []
    for (const source of sourcesSnapshot.sources) {
        claimsSnapshot.claims.push({
            ...source,
            type: "citation",
        })
    }
    await writeJsonFile(claimsPath, claimsSnapshot)
    await fs.unlink(sourcesPath)
    process.stderr.write(
        `[proposit migration] Converted ${sourcesSnapshot.sources.length} sources to citation-type claims\n`
    )
}

async function backfillClaimTypes(stateDir: string): Promise<void> {
    const claimsPath = path.join(stateDir, "claims.json")
    const snapshot = await readJsonFile<{
        claims?: Array<Record<string, unknown>>
    }>(claimsPath)
    if (!snapshot || !snapshot.claims) return
    let backfilled = 0
    for (const claim of snapshot.claims) {
        if (claim.type === undefined) {
            claim.type = "normal"
            backfilled++
        }
    }
    if (backfilled > 0) {
        await writeJsonFile(claimsPath, snapshot)
        process.stderr.write(
            `[proposit migration] Backfilled type='normal' on ${backfilled} pre-existing claims\n`
        )
    }
}

async function convertAssociationsToCitations(stateDir: string): Promise<void> {
    const oldPath = path.join(stateDir, "claim-source-associations.json")
    const newPath = path.join(stateDir, "claim-citations.json")
    const snapshot = await readJsonFile<{
        claimSourceAssociations?: Array<Record<string, unknown>>
    }>(oldPath)
    if (!snapshot || !snapshot.claimSourceAssociations) return
    const citations = snapshot.claimSourceAssociations.map((a) => ({
        id: a.id,
        citingClaimId: a.claimId,
        citingClaimVersion: a.claimVersion,
        sourceClaimId: a.sourceId,
        sourceClaimVersion: a.sourceVersion,
        checksum: a.checksum,
        // Preserve any additional properties
        ...Object.fromEntries(
            Object.entries(a).filter(
                ([k]) =>
                    ![
                        "id",
                        "claimId",
                        "claimVersion",
                        "sourceId",
                        "sourceVersion",
                        "checksum",
                    ].includes(k)
            )
        ),
    }))
    await writeJsonFile(newPath, { claimCitations: citations })
    await fs.unlink(oldPath)
    process.stderr.write(
        `[proposit migration] Converted ${citations.length} claim-source associations to citations\n`
    )
}

async function foldForkSourcesIntoClaims(stateDir: string): Promise<void> {
    const forksPath = path.join(stateDir, "forks.json")
    const snapshot = await readJsonFile<{
        sources?: Array<Record<string, unknown>>
        claims?: Array<Record<string, unknown>>
        [key: string]: unknown
    }>(forksPath)
    if (!snapshot || !snapshot.sources || snapshot.sources.length === 0) {
        // Even with no sources, we may need to drop the empty 'sources' key.
        if (snapshot && "sources" in snapshot) {
            delete snapshot.sources
            await writeJsonFile(forksPath, snapshot)
        }
        return
    }
    if (!snapshot.claims) snapshot.claims = []
    snapshot.claims.push(...snapshot.sources)
    const sourceCount = snapshot.sources.length
    delete snapshot.sources
    await writeJsonFile(forksPath, snapshot)
    process.stderr.write(
        `[proposit migration] Folded ${sourceCount} source fork records into claims namespace\n`
    )
}

async function recomputeChecksums(stateDir: string): Promise<void> {
    // Hydrate libraries via fromSnapshot, which re-derives checksums.
    // Then write back. This relies on the library's restoreFromSnapshot path
    // running through the standard checksum recomputation.
    // Implementation: import readClaimLibrary/readClaimCitationLibrary/etc.,
    // call them, then write back via writeClaimLibrary/etc.
    // Note: ClaimCitationLibrary requires a claimLookup, so order matters:
    // hydrate claims first, then citations using the populated claim lookup.
    const { readClaimLibrary, writeClaimLibrary } = await import("./libraries.js")
    const { readClaimCitationLibrary, writeClaimCitationLibrary } =
        await import("./libraries.js")

    const claimLib = await readClaimLibrary()
    await writeClaimLibrary(claimLib)

    const citationLib = await readClaimCitationLibrary({
        get: (id, version) => claimLib.get(id, version),
    })
    await writeClaimCitationLibrary(citationLib)
    process.stderr.write(
        `[proposit migration] Recomputed claim and citation checksums\n`
    )
}

async function validateAcyclicity(stateDir: string): Promise<void> {
    // ClaimCitationLibrary.add() rejects cycles. Hydrating from a snapshot
    // that contains cycles would have already thrown during recomputeChecksums
    // (which calls fromSnapshot via readClaimCitationLibrary), so by reaching
    // this point we know the data is acyclic. No-op here for clarity.
    process.stderr.write(
        `[proposit migration] Citation graph validated (no cycles)\n`
    )
}

# v0.10.0 — Source-as-Claim Unification

## Breaking changes

This release unifies the `Source` and `Claim` entity models into a single library. If you've been using `proposit-core` to author or persist propositional arguments, please read the migration notes below before upgrading.

### Highlights

- **Single claim entity.** `Source` and `SourceLibrary` are removed. All entities that were sources are now claims with a `type: "citation"` field. New entities can be created with `type: "normal"` (for primary-reasoning claims) or `type: "citation"` (for cited external content).
- **Renamed citation graph.** `ClaimSourceLibrary` is now `ClaimCitationLibrary`. Field renames: `claimId` → `citingClaimId`, `sourceId` → `sourceClaimId`. The library now takes a single `claimLookup` constructor argument (was: two lookups).
- **New invariants on the citation graph.**
  - The source-side endpoint of every citation must reference a claim with `type: "citation"`. Citing a normal claim as evidence is rejected with `CITATION_SOURCE_NOT_CITATION_TYPE`.
  - The citation graph must be acyclic. Adding an edge that would close a cycle is rejected with `CITATION_CYCLE_DETECTED`. Cycle detection is by claim ID, not by `(id, version)`.
- **Claim `type` is immutable post-creation.** Updating a claim's type throws `CLAIM_TYPE_IMMUTABLE`.
- **Wire-format change.** `TPropositCoreSnapshot` no longer has a `sources` field; `claimSources` is renamed to `claimCitations`. Apps that round-trip snapshots over HTTP must accept the new field name (no compat shim).
- **CLI command rename.** The `proposit sources` subcommand tree is replaced by `proposit citations`. The `proposit claims add` command now accepts `--type=normal|citation`.

### Migration

For consumers persisting data:

- The CLI handles its own state directory migration automatically on first v0.10.0 startup. A `.proposit-v0.10` marker file indicates migration is complete.
- Other consumers (proposit-server, proposit-mobile, external) implement their own migration. Recommended steps live at `docs/migrations/0.9.0-0.10.0.md`.
- A new validation code, `LEGACY_CLAIM_MISSING_TYPE`, is emitted by core when pre-v0.10.0 claim records are loaded, so apps can detect "I'm loading old data" and route to their migration.

### Other changes

- `ForkLibrary` now has 5 namespaces (sources are folded into claims).
- The `ArgumentParser` parsing layer drops the `TSource`/`TAssoc` generics; consumers extending the parser update their generic parameter lists.
- The IEEE extension's `IEEESourceSchema` is replaced with `IEEECitationClaimSchema` (a `type: "citation"`-narrowed claim intersect).
- Collection-level checksums for the claims and citations collections shift on day-of-upgrade. Apps that fingerprint sync state via `getCollectionChecksum("claims")` should treat the post-migration value as a reset baseline.
```

# Migrating from v0.9.x to v0.10.0

This guide describes the recommended migration steps for downstream consumers of `proposit-core` that persist data: `proposit-server`, `proposit-mobile`, and any other external consumers.

The CLI's state directory is migrated automatically; this guide is for everyone else.

## What changed

[summary of the breaking changes — claim type field, source library deletion, citation library rename, fork namespace fold, wire-format changes]

## Migration steps

For each persisted data store:

### Step 1: Detect legacy state

Look for the absence of a `type` field on persisted claim records. v0.9.x claims have only `{id, version, frozen, checksum}`. v0.10.0 claims add `type: "normal" | "citation"`.

The core library emits `LEGACY_CLAIM_MISSING_TYPE` validation codes when it encounters a typeless claim during snapshot restore — apps can use this signal as a migration trigger.

### Step 2: Convert sources to claims

Every record in your persisted source store becomes a claim with `type: "citation"`. Preserve all fields (id, version, frozen, checksum, plus any application-level extras).

If your source records have a `type` extra of their own (e.g., `type: "research-paper"`), you must rename the extra to a non-reserved name (e.g., `kind`) before migration. The core library's reserved `type` field will collide otherwise.

### Step 3: Backfill `type` on existing claims

For every existing claim record in your store, set `type: "normal"`.

### Step 4: Convert associations to citations

Every claim-source association becomes a claim citation with field renames:
- `claimId` → `citingClaimId`
- `claimVersion` → `citingClaimVersion`
- `sourceId` → `sourceClaimId`
- `sourceVersion` → `sourceClaimVersion`

### Step 5: Fold fork records

If you persist `ForkLibrary` snapshots, drop the `sources` namespace. Fold its records into the `claims` namespace (schemas are structurally identical).

### Step 6: Recompute checksums

Claim checksums change because `type` is now in the checksum. Citation checksums change because field names changed. Variables and expressions reference claims by `(id, version)` only — no expression-level checksum recompute is needed.

If you fingerprint sync state via collection-level checksums (`getCollectionChecksum("claims")`), expect a baseline shift on day-of-upgrade.

### Step 7: Validate acyclicity

After migration, hydrate `ClaimCitationLibrary` from the migrated data. The library will throw `CITATION_CYCLE_DETECTED` if any cycle is present in the legacy data — pre-v0.10.0 had no acyclicity invariant, so cycles may exist. Resolve cycles by deleting the offending citations.
