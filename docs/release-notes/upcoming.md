# Upcoming release notes

## Pipeline framework

- **Tell an LLM stage from a deterministic one before you run it.** A new public predicate, `isLlmStage(stage)`, returns `true` for a stage that must be driven by `launchStage` / `completeStage` (an LLM-background stage) and `false` for one that runs inline via `executeStage`. If you drive a pipeline stage-by-stage out of process — a durable orchestrator, a queue worker, or a webhook-driven server — this is the missing piece that lets you route each stage to the right driver straight from the pipeline definition (`deterministic: !isLlmStage(stage)`), instead of hand-maintaining a list of stage ids that silently drifts out of sync, or calling `launchStage` just to catch the error it throws. It gives exactly the same answer the launch/complete guard uses internally, so the two can never disagree — including the subtle case of a stage that runs an LLM inside its own `run` but is still driven by `executeStage` (the predicate correctly reports `false` for it).
