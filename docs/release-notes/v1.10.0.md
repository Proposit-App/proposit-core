# v1.10.0 release notes

## Background + live SSE streaming mode

The OpenAI provider now supports a third execution mode — `backgroundStreamMode: true` — that combines OpenAI's background responses with live SSE streaming. Requests are submitted with `{ background: true, stream: true, store: true }`, so the response continues generating server-side even if the client connection drops, and can be recovered later. Use this mode for long-running ingestion calls where resilience to short outages matters.

The three available modes on `createOpenAiResponsesProvider`:

| Mode                        | Option                       | Behavior                                              |
| --------------------------- | ---------------------------- | ----------------------------------------------------- |
| Foreground stream (default) | `stream: true`               | SSE consumed live; connection drop → retry            |
| Background poll             | `backgroundMode: true`       | Submit → poll until terminal; no live tokens          |
| Background stream           | `backgroundStreamMode: true` | SSE live + server keeps running after drop; resumable |

`backgroundStreamMode` takes priority over `backgroundMode` when both are set. Like `backgroundMode`, it requires `store: true` internally (not ZDR-compatible) and is restricted to the no-tools path.

## Response retrieval API

New exported function `retrieveResponse(id, options)` retrieves a stored OpenAI response by id, returning its status, output text (when completed), and token usage. A 404 (response aged out of the ~10-minute retention window) throws the new typed `ResponseNotFoundError`. Use this to check on or recover a background response after a connection drop.

## New pipeline event: `stage:llm-response-created`

`llmStage` now emits a `stage:llm-response-created` event `{ stageId, attempt, responseId }` as soon as the response id is known. In background-stream mode this fires **mid-call — while the LLM call is still streaming, before it finishes** — so a server-side handler can persist the id _before_ a possible crash. That is what makes short-outage recovery work: a call interrupted mid-generation can be re-fetched from OpenAI's stored copy (via `retrieveResponse`) instead of being re-run from scratch (which would double-charge the user). The `stage:llm-call` event also now carries an optional `rawResponseId` field.

In synchronous mode the id is only known at completion, so the event fires just before `stage:llm-call` — a weaker guarantee: a sync call that crashes mid-generation loses its id and must be re-run. Background-stream mode is the mode that earns the durable, recoverable behavior.
