# v1.3.0 release notes

Minor release adding the multi-stage v2 argument-ingestion pipeline
alongside the existing single-shot v1.

## v2-multi-stage argument-ingestion pipeline

A new `createIngestionV2Pipeline(extension)` factory is available
alongside `createIngestionV1Pipeline`. v2 decomposes argument
ingestion into a 12-stage DAG (4 deterministic + 8 LLM stages) for
higher-quality extraction on long or structured inputs.

The factory takes the same `TIngestionExtension` v1 does and produces
the same `TParsedArgumentResponse`-shaped output, so consumers can
swap pipelines without changing downstream parsing or
`ArgumentParser.build()` consumers.

What the 12-stage decomposition gives you:

- **Better source / citation extraction** — a dedicated
  `citation-source-detection` stage recognises Markdown links, named
  sources, and "according to X" patterns and routes them into
  citation-typed claims with the `url` and `title` populated.
- **Cleaner type classification** — a dedicated
  `claim-type-classification` stage refines the canonicalizer's draft
  per-claim type (normal / citation / axiomatic), so claim-type
  decisions don't have to be made under the cognitive load of also
  picking premises and writing formulas.
- **Decoupled conclusion selection** — `conclusion-selection` is a
  stage of its own; when it can't pick a single conclusion the
  pipeline reports `argument: null` with the failure text "No single
  conclusion could be selected." rather than forcing a wrong choice.
- **Deterministic compilation** — the formula strings themselves
  (`p1 implies p2`, `(p1 and p2) implies p3`, etc.) are generated by
  a deterministic stage from the relation graph + variable
  assignments. No LLM hallucination in the logic step.

The framework's per-stage progress events (`stage:start` /
`stage:end` / `stage:retry` / `stage:llm-call`, all shipping since
1.2.0) flow through unchanged — server-side UIs that subscribe to
those events for v1 work without modification for v2.

## Default extension unchanged

The `basicsExtension` shipped since 1.1.0 works with v2 out of the
box. Future extensions (`ieee`, etc.) come for free since the
factory is parameterized.

## Pipeline selection stays caller-controlled

The CLI's `parse` command and the server's
`/api/v1/argument/import/raw_text` route continue to construct the
pipeline they want. There's no global default flip in core; the
server's `INGESTION_PIPELINE_VERSION` env flag is the operational
control surface for the v1 → v2 default flip.

## Conclusion-selection now flags ambiguous arguments

When the `conclusion-selection` stage can't pick a single conclusion
(the argument has multiple terminal claims that could each plausibly
be the point), the stage emits a `NO_SINGLE_CONCLUSION` processing
failure on `PipelineResult.failures` (severity `warning`). The
overall pipeline result is the same as before — `argument: null` with
`failureText: "No single conclusion could be selected."` on the
output — but consumers that want to surface a per-stage explanation
can now read the rationale from the failure's `context.rationale`.
