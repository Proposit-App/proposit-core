# v1.4.0 release notes

## Added

- **Distinct classification for OpenAI quota exhaustion.** OpenAI
  returns _both_ transient rate-limit throttling and persistent
  budget exhaustion as HTTP 429 — they differ only in the response
  body's structured error code. Previously the provider collapsed
  both into the retryable `LLM_RATE_LIMITED` failure, so a consumer
  could not tell a self-clearing throttle apart from a hard "you've
  run out of quota" wall. v1.4.0 splits them:
    - A 429 whose body carries `insufficient_quota` now classifies to
      the new `QuotaExhaustedLlmError` and fails **fast** (no retry),
      surfacing the distinct, stable failure code `LLM_QUOTA_EXHAUSTED`.
    - Every other 429 — including any whose body is unparseable or
      lacks a recognizable code — stays on the transient
      `RateLimitLlmError` / `LLM_RATE_LIMITED` path with unchanged retry
      behavior. The safe default is always "transient and retryable,"
      never a false quota trip.

    This lets a consumer (e.g. a global AI-budget circuit breaker) match
    a stable `failure.code` instead of brittly searching the error
    message text.

- **Exported failure-code constants.** The LLM-stage failure codes are
  now exported as named constants from the package root —
  `LLM_QUOTA_EXHAUSTED`, `LLM_RATE_LIMITED`, `LLM_TRANSIENT_ERROR`,
  `LLM_NON_RETRYABLE_ERROR`, `LLM_UNKNOWN_ERROR`, and
  `OUTPUT_SCHEMA_INVALID` — so consumers can match `failure.code`
  against an imported value rather than re-typing the string literal.
  The constants live in the SDK-free pipeline layer, so importing them
  does not pull in the OpenAI provider.

- **`QuotaExhaustedLlmError` is part of the public error family.** It
  is exported from both the package root and the
  `@proposit/proposit-core/extensions/openai` subpath, alongside the
  existing `RateLimitLlmError`, `TransientLlmError`,
  `NonRetryableLlmError`, `SchemaValidationLlmError`, and
  `ToolLoopExhaustedError`. It carries the same optional `status`
  field as its siblings.

## Compatibility

Additive and backward-compatible. No change to the existing
`LLM_RATE_LIMITED` / `LLM_TRANSIENT_ERROR` behavior or to any existing
retry policy. `quota_exhausted` is intentionally absent from every
default `retryOn`, so quota errors fail fast without callers opting in.
