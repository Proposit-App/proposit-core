# v1.11.0

## Pipeline framework

- **Run a single pipeline stage, or a pipeline's finalize, from persisted upstream state.** Two new functions, `executeStage` and `executeFinalize`, let you run one stage (or the finalize step) of a pipeline on its own, given the upstream stages' previously computed outputs and outcomes — without re-running the whole pipeline. This is what an unattended, durable import flow needs: it can run each stage in its own step, save the result, and pick up where it left off. The serialized form of each stage's result is a small `{ outcome, output? }` record that round-trips cleanly through JSON, so it can be stored and read back between steps. Both functions reuse the exact same stage and finalize behavior the whole-pipeline runner uses, so a single-stage run produces identical results, events, and token-usage to the equivalent stage inside a full run.

- **Launch a long LLM stage and finish it later — a split that survives a suspend.** For long-running AI stages, two more new functions, `launchStage` and `completeStage`, split one stage into "submit the request and get its id back right away" and "validate the finished response later". A durable workflow can launch the request, save the id, pause without holding a connection open for the whole call, and resume to validate the result once it's done — instead of blocking a single step for the full duration of the model call. When a finished response needs another try, `completeStage` reports a retry reason code so the workflow retries exactly the cases the in-process runner would (and never retries a definitively-failed or content-filtered response). Launching a long LLM stage this way needs the OpenAI provider's new `submitBackgroundResponse` helper, which submits a background request and returns its id without waiting for it to finish.
