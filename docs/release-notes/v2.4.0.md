# v2.4.0 — Conversation primitive + terminal Argument Builder

## Public API: `conversation` primitive

A new `conversation` module introduces a stateful multi-turn LLM exchange
primitive for core. It is the foundation the server's Argument Builder
rewires onto in the next step.

- **`createConversation(deps)`** — returns a conversation object holding
  the response-ID chain and cumulative token usage. Methods:
  `.turn(stage, input, opts?)` runs one turn; `.close()` seals the
  conversation; `.turn` after `.close()` throws.
- **`executeTurn(stage, input, deps)`** — a stateless single-turn wrapper
  that runs one `TStage` through the pipeline machinery (retry, validation,
  events, token accounting), threading `previousResponseId` into the LLM
  request and surfacing `responseId` in the result.
- **Contract types**: `TMultiTurnInput<I>` and `TMultiTurnOutput<O>` for
  schema composition.

## Public API: builder extension

New `builder` subpath (`@proposit/proposit-core/builder`) provides three
`TStage` factories for the Argument Builder turns:

- **`createReviewTurn(model)`** — Socratic reviewer stage. Examines the
  user's argument, asks probing questions, provides feedback.
- **`createSimulateTurn(model)`** — Play-the-user stage. Generates a
  simulated user message challenging the argument. Discardable (not
  chained forward).
- **`createDistillTurn(options)`** — Conversation distillation stage. Reads the
  full user↔reviewer transcript and emits clean single-author prose
  (`{ argumentText: string }`). The consumer feeds this prose into the existing
  ingestion pipeline (`createScribePipeline`) to get a schema-valid
  `TParsedArgumentResponse`. One parser — finalize's output matches ingestion
  by construction, eliminating the `type`/`role` schema drift that plagued the
  original one-shot parse. Calls an `onClose` callback after completing.

## Public API: LLM provider support

- **`TResponseId = string`** brand type on `TLlmRequest.previousResponseId`
  (additive, non-breaking). The OpenAI provider threads it as
  `previous_response_id` on the Responses API request. The chat-completions
  provider ignores it (synchronous, no response-IDs).

## CLI: Terminal Argument Builder

A new interactive REPL (`node dist/cli/builder-repl.js`) gives core its
first interactive command surface:

- Type a line → review turn → print the assistant reply.
- `/simulate` → simulate turn → print the simulated user message.
- `/distill` → distill turn → render the distilled prose → close the
  conversation → exit.
- `/quit` → exit.
