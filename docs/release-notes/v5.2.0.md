# v5.2.0 release notes

## Changed

### Every ingestion stage runs on gpt-6-sol

Both import pipelines, Scribe and Scholar, now use `gpt-6-sol` for every model
call by default, keeping each stage's reasoning effort. The model names
`gpt-6-sol` and `gpt-6-luna` are known to `TLlmModel`, and the reasoning
efforts GPT-6 adds (`none`, `xhigh`, `max`) to `TReasoningEffort`. GPT-6 does
not accept `minimal`; a configured `minimal` is sent as `low` to a GPT-6
model rather than failing the request.

### An import that finds no argument asks again, then says so

The model is asked for the connections the author actually makes, and told not
to invent support the text does not give. When a text has at least two claims
but the model connects none of them, the stage is asked once more. If the second answer is empty too, the import fails
with "Couldn't work out how these claims connect to a conclusion." instead of
finishing with no argument. Out of process, pass the upstream outputs and input
to `completeStage` to get the same check there. Other runs that end without a
conclusion return that same sentence as their `failureText`.

### Premises no longer share a title

A step the model titled like an earlier one is titled from its claims instead,
and a `PREMISE_TITLE_DUPLICATE` warning is recorded in the rare case that
still repeats.

## Added

### Quotes the model reworded or spliced still get an anchor

`locateSourceAnchor` (and so finalize's claim and premise anchors) now
falls back to a careful approximate match when a quote is not in the text as
written: a quote with a word or two changed ("compared with" for "compared
to") anchors to the passage it came from, and a quote stitched together from
two passages anchors to its longest word-for-word part. It stays
conservative, because a wrong highlight is worse than none: short quotes never
match loosely, the word-for-word part of a stitched quote must be at least
eight words, at least half the quote, and found only once in the text, and
when two passages fit equally well there is no anchor (reported as
`SOURCE_ANCHOR_AMBIGUOUS`). Accented letters match however they are encoded,
and "ended—and" matches "ended and". The anchor is always the document's own
text. Each such match is reported as a `SOURCE_ANCHOR_APPROXIMATE` warning
naming the rule, so approximate matches can be counted separately from
misses (`SOURCE_ANCHOR_UNRESOLVED`).

## Fixed

### A conclusion is never titled like the step that reaches it

An imported conclusion premise could carry the same title as the premise
before it. A conclusion title that repeats any step's title is now replaced
by the conclusion claim's own title.

### Premise titles never show internal claim ids

A model-written title such as "Inference from c1" named a claim by an id no
reader ever sees. Such a title is now replaced by one built from the claims
themselves.

### Scribe attaches every linked source to the claim it supports

Arguments imported with `createScribePipeline` could come back with source
(citation) claims that backed nothing: `derivationBacking` only listed a source
when the structure stage happened to use it as an antecedent, and that stage
never sees the text. Now each source backs the claim it is offered as evidence
for — the one the extract stage names, or, failing that, the claim stated where
the link sits, elsewhere in its sentence, or just before it. The extract stage is also told to make every
link offered as evidence its own source claim. Expect more `derivationBacking`
entries from scribe runs, and three new warnings in `processingFailures`:
`SOURCE_ATTACHMENT_INVALID_SOURCE`, `SOURCE_ATTACHMENT_INVALID_TARGET` and
`SOURCE_ATTACHMENT_UNATTACHED`. A source claim, and a normal claim only a
source backs, now has the `role` `"premise"` rather than `"intermediate"`. The
pipeline's version is now 1.1.0.

Axiomatic claims are attached the same way, so an appeal to a principle backs
the claim it justifies instead of backing nothing. One claim is never backed by
both a citation and an axiom; an axiom that would be is left off, with a
`SOURCE_ATTACHMENT_MIXED` warning.

### Scribe no longer invents source links

A source's link is kept only when the imported text contains it. The model had
been building links from bare site names in a reference list
("www.gutenberg.org" became `https://www.gutenberg.org/`). Such a link is now
removed, the source itself is kept, and a `SOURCE_URL_NOT_IN_TEXT` warning
names it. Differences in capital letters in the scheme and host, `http` for
`https`, and a trailing slash, still count as the same link, and the link is
stored as the text writes it.

### Scribe merges repeated links to one source

A reference list often links the same work more than once — an archived copy
beside the original, `…/index.html` beside `…/`, `http` beside `https`. Each
used to become its own source. They are now merged into one source that backs
every claim any of them backed, and a `SOURCE_DUPLICATE_MERGED` warning names
them. Links to different pages of a site stay separate; links to different
places in one page (after a `#`) are merged.

### Scribe skips quoted text

Lines beginning with `> ` are treated as a quote of someone else — typically the
comment being replied to — and are no longer extracted as the author's own
claims.

### Symbols that begin with "not", "and" or "or"

`parseFormula` read a symbol such as `NotProofOfGod` as "not ProofOfGod", which
left an imported premise pointing at a symbol that does not exist. Word
operators now have to stand as whole words.
