# Release notes — v0.11.2

## Bug fixes

- **`ManagedDerivationPremiseEngine.populateFromCitations` now produces canonical formula-buffered shape for n ≥ 2 citations.** Previously, when populating a derivation premise from two or more citations, the helper temporarily switched to permissive grammar and produced `IMPLIES(OR(s1, …, sn), Q)` — the OR sat directly under IMPLIES with no formula buffer. Every other engine path (manual rebuild, auto-normalize on load) produces the canonical `IMPLIES(formula(OR(s1, …, sn)), Q)` shape. The two shapes are both valid per `validateDerivationStructure`, but they hash to different `combinedChecksum` values, which caused consumer-side normalization checks to falsely report drift on cited arguments. The helper now uses standard grammar throughout so its output matches what every other path emits. Stored pre-v0.11.2 trees remain valid; consumers that rely on checksum equality may want to run a one-time normalization pass to converge them to the canonical shape.
