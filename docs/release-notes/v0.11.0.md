# Release notes — v0.11.0

This release introduces structurally-constrained derivation premises.

## What's new

- **Derivation premise type.** Every premise now carries `type: "freeform" | "derivation"`. Derivation premises also carry a required, immutable `derivedClaimId` — a structural commitment to deriving a single named claim. The classic freeform premise is unchanged.

- **`ManagedDerivationPremiseEngine`.** Opt-in subclass of `PremiseEngine` that enforces the derivation invariant on every mutation: you cannot edit the consequent slot, cannot change the root operator inappropriately, and cannot bulk-load a malformed expression set. The classic engine remains permissive — temporarily-invalid states are allowed mid-mutation and caught at evaluation time.

- **`populateFromCitations` helper.** One-shot citation snapshot. Builds the antecedent from the citation library's current edges: `n=0` leaves the premise as naked-Q (a structural symptom of "no support given"); `n=1` produces `IMPLIES(S1, Q)`; `n≥2` produces `IMPLIES(OR(S1, ..., Sn), Q)`.

- **`ensureClaimBoundVariable` API.** Idempotent variable materialization on `ArgumentEngine`. Useful beyond `populateFromCitations` for apps that programmatically reference claims.

- **Evaluation pre-flight.** `ArgumentEngine.evaluate` and `checkValidity` now refuse to silently proceed on a structurally-broken derivation premise — they return a validation result with `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION`.

- **CLI support.** New `premises create --type=derivation --derived-claim=<id>` and `premises populate-citations <premiseId>` subcommands. Derivation premises render with a `[derivation]` badge, mirroring the `[citation]` convention from v0.10.0.

- **YAML examples support derivation premises.** New optional `claims:` block + `type: "derivation"` and `derivedClaimId:` fields on premises in YAML imports.

## Migration

Pre-v0.11.0 premise records are automatically backfilled with `type: "freeform"` on first CLI invocation. A `.proposit-v0.11` marker in your state directory indicates the migration has run.

## Soft-breaking changes

- `createPremise` and `createPremiseWithId` accept a new typed-bag options argument. Legacy positional calls `createPremise(extras, symbol)` continue to work via overload — no source changes required for existing call sites. New code should prefer the typed bag for clarity.
- `TClaimLookup.getCurrent` is now required (was optional). Test code that mocked `TClaimLookup` with a bare `{ get }` object must add `getCurrent`.
