# v3.3.0 release notes

## Changed

- **Dates are converted with `Value.Decode` now, not `Value.Convert`.** The
  library supports typebox 1.3, which removed the base-type API the date schema
  was built on. `EncodableDate` still accepts either a `Date` or the date string
  `JSON.stringify` produces, and still gives back a real `Date` — but the step
  that performs the conversion has moved. Code that leaned on `Value.Convert` to
  turn a stored date string back into a `Date` now receives the string
  unchanged, with no error raised, so it needs to move to `Value.Decode`.
- **Checking a value against a date field accepts the serialized form.** It
  previously required a real `Date` object. A numeric value supplied where a date
  belongs is still rejected, so that mistake still fails validation as it did
  before.
